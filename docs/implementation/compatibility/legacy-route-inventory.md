## Method

The M04 inventory is derived from the reviewed M01 API inventory rather than
from an unreviewed text grep.

PR 04F preserves the baseline evidence fields and adds M04 classification,
target-route status, deprecation status, and removal gates.

Management routes remain `UNKNOWN` until a dedicated compatibility PR
classifies them. Protocol routes are classified separately because external
client compatibility governs their lifecycle.

## Runtime Registration

The application host now registers inherited route modules through explicit
compatibility entry points:

`	ext
registerTunarrLegacyApiRoutes
registerTunarrLegacyStreamRoutes
`

The wrappers preserve the existing registration grouping:

`	ext
legacy API group:
  HDHomeRun router
  /api router

legacy stream group:
  video router
  stream router
`

Host bootstrap/static routes remain host-owned and remain inventoried where
present in the reviewed M01 inventory.

`	ext

`

`DEPRECATE`.

`	ext

`

`	ext

`

## PR 04G Adapter Proof

The first route adapter proof is intentionally narrow:

```text
GET /api/settings/media-source
PUT /api/settings/media-source
```

The inherited HTTP DTO remains:

```json
{
  "rescanIntervalHours": 6
}
```

The ChannelForge Media Sources application contract uses:

```text
intervalHours
```

Translation is explicit in both directions.

The write route does not create a second writer. ChannelForge validates the
command through its application service, then the compatibility store writes
the inherited Tunarr settings authority.

Deprecation planning metadata is registered now, but the route is not marked
deprecated until a public replacement management route exists.

    Method¶

    The M04 inventory is derived from the reviewed M01 API inventory rather than from an unreviewed text grep.

    PR 04F preserves the baseline evidence fields and adds M04 classification, target-route status, deprecation status, and removal gates.

    Management routes remain UNKNOWN until a dedicated compatibility PR classifies them. Protocol routes are classified separately because external client compatibility governs their lifecycle.

    Runtime Registration¶

    The application host now registers inherited route modules through explicit compatibility entry points:

    ext registerTunarrLegacyApiRoutes registerTunarrLegacyStreamRoutes

    The wrappers preserve the existing registration grouping:

    ` ext legacy API group: HDHomeRun router /api router

    legacy stream group: video router stream router `

    Host bootstrap/static routes remain host-owned and remain inventoried where present in the reviewed M01 inventory.

    Tags and Metrics¶

    Visible compatibility-registered routes receive:

    ext legacy compatibility

    deprecated is added only after a route is explicitly classified DEPRECATE.

    Usage records:

    ext LEGACY_ROUTE_CALLS COMPATIBILITY_LATENCY

    A future deprecated route additionally records:

    ext DEPRECATED_ROUTE_CALLS

    Metrics use the Fastify route template, never a concrete request URL.
